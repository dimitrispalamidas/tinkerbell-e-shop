TINKERBELL - TRANSLATION POLICY (Ternary-First)
===============================================

Last Updated: November 2024
Approach: Ternary-First (Inline Visibility)

===============================================
🎯 PRIMARY RULE: USE TERNARIES
===============================================

DEFAULT APPROACH: Use inline ternary operators for ALL user-facing text

✅ ALWAYS USE TERNARIES:
```tsx
import { useLocale } from 'next-intl';

const locale = useLocale();

// Simple text
<p>{locale === 'el' ? 'Ελληνικό κείμενο' : 'English text'}</p>

// With variables
<p>{locale === 'el' ? `Μόνο ${count} διαθέσιμα` : `Only ${count} available`}</p>

// Database fields
<h1>{locale === 'el' ? product.name_el : product.name_en}</h1>

// Buttons, labels, messages - EVERYTHING!
<Button>{locale === 'el' ? 'Αποθήκευση' : 'Save'}</Button>
```

WHY TERNARIES?
✅ Instant visibility - see both languages at once
✅ Easy to spot inconsistencies with your eyes
✅ No need to jump between files
✅ Faster development and debugging
✅ Self-documenting code

===============================================
✅ CONSISTENCY CHECKLIST
===============================================

Before committing code, visually scan for:

1. SPELLING: Are Greek/English texts correct?
   ✓ "Αποθήκευση" not "Αποθηκευση"
   ✓ "Save" not "Sav"

2. CONSISTENCY: Same text = same translation
   ✓ "Save" always "Αποθήκευση" (not "Αποθήκευση" / "Σώσιμο")

3. COMPLETENESS: Both languages present?
   ✓ {locale === 'el' ? 'ΕΛ' : 'EN'} ✅
   ✗ {locale === 'el' ? 'ΕΛ' : ''} ❌

4. VARIABLES: Same variables in both?
   ✓ {locale === 'el' ? `Μόνο ${x}` : `Only ${x}`} ✅
   ✗ {locale === 'el' ? `Μόνο ${x}` : `Only ${y}`} ❌

===============================================
🔧 HELPER FUNCTION
===============================================

For database fields, you can use the helper:

```typescript
// lib/utils/translate.ts
export function getLocalizedField<T>(
  obj: T, 
  field: string, 
  locale: string
): string {
  const key = `${field}_${locale}` as keyof T;
  return (obj[key] as string) || '';
}

// Usage:
const name = getLocalizedField(product, 'name', locale);
const desc = getLocalizedField(product, 'description', locale);
```

But direct ternaries are also fine:
```tsx
{locale === 'el' ? product.name_el : product.name_en}
```

===============================================
🚫 WHAT NOT TO DO
===============================================

❌ Don't hardcode only Greek:
<Button>Αποθήκευση</Button>  // Missing English!

❌ Don't hardcode only English:
<Button>Save</Button>  // Missing Greek!

❌ Don't use JSON for one-off text:
<Button>{t('save_button_in_checkout_page')}</Button>  // Overkill!

❌ Don't forget the ternary:
<p>Ελληνικό κείμενο</p>  // Where's English?

===============================================
💡 PRO TIPS
===============================================

1. COPY-PASTE TEMPLATE:
   {locale === 'el' ? '' : ''}
   Fill in the blanks!

2. USE FIND/REPLACE:
   If you need to change a translation, use VS Code's 
   Find in Files to locate all instances.

3. VISUAL SCAN:
   Ctrl+F for "locale ===" to see all translations
   in a file at once.

4. CONSISTENCY CHECK:
   Search for common words:
   - "Save" / "Αποθήκευση"
   - "Cancel" / "Ακύρωση"  
   - "Delete" / "Διαγραφή"
   
   Make sure they're always the same!

===============================================
🔍 SCANNING FOR INCONSISTENCIES
===============================================

To scan your project for translation issues:

```bash
# Find all ternaries
grep -r "locale === 'el' \?" --include="*.tsx" --include="*.ts"

# Find potential missing translations (hardcoded Greek)
grep -r "[Α-Ωα-ω]" --include="*.tsx" | grep -v "locale ==="

# Find potential missing translations (hardcoded English in JSX)
grep -r "<[^>]*>[A-Z][a-z]" --include="*.tsx" | grep -v "locale ==="
```

Or just ask an AI to scan it! 🤖
